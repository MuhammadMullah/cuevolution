01 · Foundations

Design principles

Five commitments that every screen inherits, from the marketing hero down to a dense results-entry table.

01

Modern, clean, sleek

Generous whitespace, restrained color, soft elevation instead of heavy borders and shadows.

02

Mobile-first

Most players register and check standings from a phone on Kenyan mobile networks. Design the smallest breakpoint first.

03

Data-legible

This is a standings and results product. Points, scores, rankings and times must be instantly scannable — hence tabular mono numerals.

04

One language everywhere

Landing, player app and admin share the same tokens. The console is denser — never a different skin.

05

Alive, not jumpy

LiveView updates — standings ticking up, inline validation — use short, calm transitions. Never layout jank.

02 · Color

Color

The neutral ramp is a warm, near-black ink scale. #0D0C22 is the primary brand and primary-action color. Kenya Red (#E32219) and Kenya Green (#16A34A) — both drawn from the Kenya Pool Billiard Federation logo — are the secondary accents for links/active states and success/qualification respectively.

Ink / neutral scale — warm near-black

Only ink-900 is interpolated; every other step is a deliberately warm (not cold) gray.

Usage rules
  • Never use color alone to convey meaning — always pair status/stage with an icon or label.
  • Default surface is light (ink-25 / ink-50); ink-950 is a deliberate dark band for nav, footer and hero — not a full dark theme.
  • One severity palette. If a state doesn't fit success / warning / danger / info, the design is wrong, not the taxonomy.

07 · Motion

Motion

  • Hover / focus: 150ms ease-out.
  • LiveView updates: 200ms ease-out, fade + slight slide — never an abrupt swap.
  • Respect prefers-reduced-motion — disable non-essential animation.
08 · Accessibility

Accessibility

  • Body (ink-700 on ink-25) and inverse (white on ink-950) both exceed WCAG AA.
  • Every interactive element keeps a visible red-500 focus ring — never outline-none without a replacement.
  • Status and stage always carry an icon or label, never color alone.
  • Every input has a <label>; errors linked via aria-describedby.
